## 配图写法对照

**错误：待补占位 / 图说解说**

```markdown
![上传（待补截图）](./images/upload.png)

上图是上传后的预览区……
（图片说明：……）
```

**正确：有真实文件，只插图**

```markdown
打开页面，上传图片。

![上传后的预览](./images/upload.png)

工具会在本地读取像素……
```

## 配图获取对照

| 需要的图 | 正确做法 | 错误做法 |
|----------|----------|----------|
| 本站工具上传区 | 打开工具 URL → 自动截图 → 写入 `images/` | 写「待补截图」 |
| SEO「图书馆」隐喻氛围图 | Unsplash/Pexels 检索，合适再下载 | 百度搜图乱下 |
| 抓取→索引→排序流程 | 手绘风示意图（Mermaid 或 AI） | 光滑商务 PPT 风 / 不相关风景照 |
| 图库无合适概念图 | 手绘风 AI 示意 | 爬竞品官网 UI；正文写长图注 |

## 代码写法对照

**缺节奏（避免）：**

> 你可以用这行：`fetch(url)` 然后怎么样怎么样……（全埋在段落里）

**达标（采用）：**

> 下面是一个最小请求例子。
>
> ```js
> const res = await fetch('/api/data');
> const data = await res.json();
> ```
>
> 上面代码中，`fetch` 默认使用 GET；用 `await` 是为了把异步写得更直白。

## 检查用「读出声」测试

写完后默读：

1. 前 150 字能否让外行知道「这是什么、我为什么要读」？  
2. 有没有连续超过 4 行的大段说教？有则拆段。  
3. 第一个术语是否在出现时用括号标了英文？  
4. 是否出现「赋能」「抓手」「闭环」等空话？有则删。  
5. 是否有真实图片、且没有「上图是 / 图片说明」？该动手处有没有短代码？  
6. 工具步骤是否已自动截图？主题图是否优先走了 Unsplash/Pexels？
