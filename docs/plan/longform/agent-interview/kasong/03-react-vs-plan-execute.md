# ReAct 和「先计划再执行」，谁也不会一统 Agent

> 文风版本：**卡颂向**（对照原文 [`../03-react-vs-plan-execute.md`](../03-react-vs-plan-execute.md)）  
> 系列第 3 题 · 图片复用  
> [上一题](./02-when-not-to-use-agent.md) · [地图](./00-series-map.md)

大家好。

Agent 面试里，ReAct 大概是被背得最滥的一个缩写。

很多人能把 Reason + Act 三个音节念出来。

下一句问 Observation（观察）在哪、什么时候该先写计划，就开始漂。

另一拨人站队更狠：要么「必须 ReAct 才叫智能」，要么「没有 Planner 就是玩具」。

恰恰相反。生产里两者经常嵌在一起。

本文不站队。只给一个能带走的选型旋钮。

---

## 原题

> ReAct 在做什么？和 Plan-and-Execute（先规划再执行）有什么区别？你会怎么选？

考察点：

- 是不是真懂 Thought / Action / Observation
- 能不能对比「边做边改」和「先路书后开车」
- 维度是否工程化：反馈密度、计划稳不稳、好不好审、贵不贵
- 知不知道可以混合

---

## ReAct：局势善变时，别空画饼

所谓 ReAct，指的是把推理和行动写在同一条循环里：

1. Thought：根据目标和观察，想下一步
2. Action：调工具
3. Observation：把返回塞回上下文
4. 重复，直到完成或撞上终止条件

本质上是：**边做边根据环境反馈改主意**。不要求一开始就有完整计划。

Function Calling 解决的是「怎么调工具」。  
ReAct 解决的是「何时想、何时调、看完结果怎么继续」。

两者不是一回事。可以没有论文里那种 Thought 字段，但得有等价循环。

---

## Plan-and-Execute：步骤长、要人审时，先路书

典型两段：

1. Plan：先产出步骤列表，最好人类可读、可审
2. Execute：逐步执行；每步可以是工具或子 Agent
3. 偏了就 re-plan（重规划）

本质上是：**先把路径显式化，再消耗工具额度**。规划和执行甚至能换不同模型——强模型写计划，小模型或脚本干活。

注意：计划如果是人写死的图，那是 Workflow，别混称。  
计划是运行时模型生成的，才还在 Agent 族里。

## 选型就三个旋钮

| 更偏 ReAct | 更偏 Plan-and-Execute |
|---|---|
| 反馈密，下一步强依赖观察 | 步骤多、结构清楚、要人审计划 |
| 事先计划容易作废 | 要并行子任务、控成本 |
| 短链路探索 | 长链路，需要可审计的计划快照 |

一句话：`反馈密、局势善变 → ReAct；目标可拆、要审计划 → Plan-and-Execute。`

信息何时到达，决定你能不能先写长计划。

编译报错、页面 DOM、检索命中——这些必须靠工具才看得到，硬写长计划容易空。ReAct 更自然。

迁移清单、发布检查单——先验结构很强，先计划能少「乱逛式」调工具。

成本也不站队。ReAct 步数失控时账单难看。Plan-and-Execute 规划错了会错一整段，所以重规划次数也要封顶。

---

## 生产里，混合才是常态

- 高层 Plan-and-Execute，某一步内部再 ReAct
- ReAct 跑 N 步后强制小结成计划，方便日志和人工介入
- 计划必须过 HITL，执行阶段才放开工具

能说出混合，比背论文名像干过活。

多 Agent 也不是 Plan-and-Execute 的别名。前者是角色 / 实例怎么拆，后者是时间上的两阶段。可以正交组合。

失败了怎么办？检测偏差 → 重规划或回退检查点；限制次数；有副作用的步骤要幂等或事务。

评测也很土：同一任务集比成功率、步数、费用、人工介入率、计划遵守率。

---

## 翻车红旗

- 「ReAct 就是 Chain-of-Thought」——忘了 Act / Observation
- 只会说哪个「更好」，给不出任务条件
- 说 Plan-and-Execute 必须绑某个框架
- 画 ReAct 没有观察、没有终止
- 认为二者互斥，生产里不能嵌

白板左边一个环：

```text
Thought → Action → Observation → Thought …
```

右边两段：

```text
[Planner] → 计划草案 →（可选人审）→ [Executor]
                              ↑ 偏差大则 re-plan
```

下面三个旋钮：`反馈密度` · `计划稳定性` · `是否要审计划`。

---

## 总结

ReAct 是交错式「想-做-看」。  
Plan-and-Execute 是「先路书后开车」。

谁也不会一统。选谁，看环境反馈有多密、计划能稳多久、以及你要不要把计划拿给人审。

这个分析基于已有工程实践，不建立在「未来模型一次规划永远正确」的假想突破上。
