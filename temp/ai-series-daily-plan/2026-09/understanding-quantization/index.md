Quantization（量化）是把模型权重从 FP16 / FP32 **压到低精度整数（如 INT8、INT4）**，换更小的体积和更快的推理。

本地跑 70B 模型、手机端部署、降低云端 GPU 成本——量化几乎是必经步骤。但 INT4 到底损失什么，值不值得，得先搞清楚。

下面是我整理的量化要点：压的是什么、精度阶梯、以及怎么选。

![量化精度阶梯：FP32 → FP16 → INT8 → INT4](https://ik.imagekit.io/4pjac7gmxh/blog/2026/09/quantization-precision-ladder_AEKglUvaI.png)

## 一、先说一个具体麻烦

一个 7B 参数的模型，FP16 权重约 14 GB 显存——消费级显卡单卡装不下。量化到 INT4 后，体积 roughly 缩到 1/4，4～5 GB 就能跑。

代价呢？偶尔答案差一个词、数学略偏、长上下文一致性下降——**不是随机坏，而是数值精度不够导致的系统性折损**。

## 二、量化在压什么

神经网络核心是大量矩阵乘法，权重是浮点数。量化做两件事：

（1）**降低每个权重的比特数**—— 例如从 16 bit 压到 4 bit  
（2）**用缩放因子（scale）和零点（zero point）** 把浮点范围映射到整数区间

```text
# 示意：FP16 权重 0.347 → INT4 只能表示 16 个离散级别
# 量化后可能变成 0.35，引入舍入误差
```

上面只是直觉示意；实际方案（GPTQ、AWQ、GGUF 等）在舍入策略和校准数据上各有优化。

![FP16 精细数值 vs INT4 粗粒度表示](https://ik.imagekit.io/4pjac7gmxh/blog/2026/09/quantization-fp16-int4_Vv9ryoKx5M.png)

## 三、常见精度档位

| 格式 | 每权重约 | 相对体积 | 典型用途 |
| --- | --- | --- | --- |
| FP32 | 32 bit | 1×（基准） | 训练 |
| FP16 / BF16 | 16 bit | ~0.5× | 训练与推理 |
| INT8 | 8 bit | ~0.25× | 推理加速 |
| INT4 | 4 bit | ~0.125× | 本地/边缘部署 |

比特越少，**可表达的权重值越稀疏**，累积误差在深层网络里放大。

## 四、INT4 主要损失什么

（1）**数值精度**—— 权重舍入，极端依赖小数值的层（如 LayerNorm 附近）更敏感  
（2）**长尾能力**—— Rare token、复杂推理、多步数学，误差更容易暴露  
（3）**校准依赖**—— 量化用校准集估 scale，校准集和实际任务分布差太远，效果掉得更明显

不一定损失什么：**大部分日常对话、摘要、格式转换**，INT4 与 FP16 体感差距可能很小——取决于模型大小、量化方案与任务。

## 五、怎么选

（1）**先试 INT4 能否接受**—— 用你的真实 Prompt 集 A/B，别只看 benchmark。  
（2）**关键任务用 INT8 或 FP16**—— 医疗、法律、精确计算留余量。  
（3）**看方案而非只看 bit 数**—— AWQ、GPTQ、GGUF Q4_K_M 等同为 4 bit，质量可差一截。  
（4）**大模型 INT4 往往更稳**—— 7B INT4 和 70B INT4 的可信度不在一个量级。

**KV Cache 也可量化**：推理框架有时提供 INT8/FP8 Cache，进一步省显存，代价是 Attention 略损精度——与权重量化是不同层级的折中。

### 5.1 何时不必量化

若显存够、任务敏感（长链推理、精确数值），直接用 FP16/BF16 推理最省心。量化是**资源不够时的工程选项**，不是品质提升手段。

部署前要跑一遍自己的 golden set：同一批 Prompt，对比 FP16 与 INT4 的输出差异。若只有极少数长尾用例退化，可接受；若核心 KPI（代码通过率、JSON 合法率）明显掉点，应退回 INT8 或换更大 bit 的 GGUF 档，而不是硬上 INT4 省显存。

```bash
# 示意：指定 GGUF 量化档
./llama-cli -m model-Q4_K_M.gguf -p "你好"
```

上面命令中，`Q4_K_M` 是 4 bit 混合精度的一种变体，比纯 Q4_0 通常质量更好。

## 六、常见误区

（1）**量化 ≠ 蒸馏**—— 量化压精度，蒸馏是训小模型模仿大模型，是两条路。  
（2）**INT4 不是越狠越好**—— 过度量化不如换小一号 FP 模型。  
（3）**训练仍要 FP**—— 量化模型主要用于推理；训练阶段一般不用 INT4 权重更新。  
（4）**同一 bit 不同方案差很大**—— 对比时要锁定 GPTQ / AWQ / GGUF 等具体实现。

## 七、小结

量化用低精度整数压缩权重，换体积和速度。INT4 损失的主要是数值精度与长尾任务上的稳定性，日常任务往往可接受。选型时以你的真实 workload 实测为准，别只看 bit 标签。

与 KV Cache 篇对照：权重量化让模型塞进更小显存；Cache 量化让推理过程少占显存。两者叠加能跑更长上下文，但错误也会叠加——压得越狠，越要靠实测而不是纸面参数做决定。量化没有免费午餐，只有可接受的 trade-off。

云端 API 通常已选好精度，用户不直接选 INT4；本地 Ollama、llama.cpp 才常遇到 GGUF 档位的选择。弄清 INT4 损失什么，是为了**本地下载模型时不被文件名里的 Q4、Q8 搞晕**。

混合精度量化（不同层不同 bit）是常见折中：注意力层保留更高精度，MLP 层压得更狠。文件名里的 `K_M`、`K_S` 等后缀，往往表示这种混合策略——下载前看一眼社区评测，比只看体积数字靠谱。

量化也分「权重量化」与「激活量化」。本文主要谈权重 INT4；激活量化进一步省算力，但实现与硬件绑定更深。消费级讨论里提到 INT4，多半指权重——别和 W8A8 等方案混为一谈。先搞清对象，再读 benchmark 才有可比性。
