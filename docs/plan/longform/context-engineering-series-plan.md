# Context Engineering 专题 · 总规划

> ⏳ **候选系列 · 待二次筛选**（见 [`00-longform-shortform-focus.md`](../00-longform-shortform-focus.md)）  
> AI 系列 Phase 3 有单篇概念；本系列拉成 **可独立阅读的短专题**，不绑 80 篇大部头。
>
> 姊妹系列：`ai-series-plan.md` · `agent-interview-series-plan.md` · `tech-depth-series-plan.md`
>
> 本系列定位：觉得「Prompt 调不动了」、要管理系统上下文的工程师  
> 核心承诺：每篇一个可迁移的上下文设计模式 + 反例  
> 风格锚点：生活类比 → 模式定义 → 伪代码/配置 → 何时不用，1800–2800 字/篇  
> 发布平台：个人博客（主）· 掘金 · 知乎 · X  
> 规模：**12 篇**短系列（适合一次读完）

## 篇目

| 序 | 主题 |
|---|---|
| 1 | Context Engineering 是什么：从 Prompt 到「状态供氧」 |
| 2 | 上下文预算：Token 是地租，怎么分配给指令/记忆/工具/检索 |
| 3 | 指令层：稳定规则 vs 易变任务，分层怎么放 |
| 4 | 工作记忆：当前目标、草稿、中间结果放哪 |
| 5 | 情节记忆与长期记忆：写入策略与污染防治 |
| 6 | 检索即上下文：塞原文、塞摘要、塞引用，三种代价 |
| 7 | 工具结果回填：成功/失败/截断时的上下文卫生 |
| 8 | Lost in the Middle：长上下文的摆放与重排 |
| 9 | 多 Agent 的上下文接口：传什么、不传什么 |
| 10 | 缓存友好的上下文：前缀稳定才能吃到 Prompt Cache |
| 11 | 评测上下文策略：换上下文不换模型，指标怎么设计 |
| 12 | 复盘清单：上线前的 Context Review（可打印） |

## 每篇结构模板

```
【钩子】一个「上下文塞错」导致的真实翻车
【模式】一句话定义 + 适用边界
【做法】步骤 / 伪代码 / 配置片段
【反例】常见错误塞法
【自测】3 个检查问题
【关联】链到 AI 系列 / 面试题对应篇
```
