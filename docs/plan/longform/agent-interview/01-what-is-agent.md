# Agent 面试｜第 1 题｜什么是 Agent？和 Chatbot / Workflow 的边界

> 系列：[第 0 题 · 地图](./00-series-map.md) · 下一题：[第 2 题｜什么时候不该用 Agent？](./02-when-not-to-use-agent.md)

---

## 原题

**中文常见问法：**

> 你怎么定义 Agent？它和 Chatbot、Workflow（工作流）有什么区别？你们项目里为什么叫 Agent，而不是「多轮对话」或「流程引擎」？

**英文常见问法：**

> What is an AI agent? How is it different from a chatbot or a deterministic workflow?

---

## 考察点

（1）有没有清晰边界，而不是背「自主」「智能」空话。  
（2）能不能从**控制权**讲：谁决定下一步——人、规则图，还是模型。  
（3）是否承认失败模式：循环、成本、不可预测性。  
（4）表达是否能画出来（白板友好）。

---

## 过关答

我用三句话先立边界，再展开。

**Chatbot（聊天机器人）**：以对话为界面，主产出是文本。可以多轮，也可以接检索，但通常**没有**「模型自己选工具、执行、再观察、再决策」的闭环；下一步多半由用户继续提问驱动。

**Workflow（工作流）**：步骤事先画在图里（或写在编排代码里）。大模型可以是其中一个节点，但**分支与顺序主要由规则或编排器决定**，可预测、易回放、易审计。

**Agent（智能体）**：给一个**目标**，在工具集与策略约束下，由模型在循环里决定「想什么、调什么工具、何时停」。典型回路是：思考 → 选工具 → 执行 → 观察 → 再思考，直到满足终止条件。

![Chatbot、Workflow、Agent 三者边界](https://ik.imagekit.io/4pjac7gmxh/blog/01-boundary_ewRcIPoWV.png)

所以，我判断是不是 Agent，不看产品文案里有没有这个词，而看三点：

（1）有没有**目标驱动的多步循环**。  
（2）下一步是否主要由**模型决策**（在允许的工具与策略内）。  
（3）有没有明确的**终止条件**（步数、预算、成功判据、人工打断）。

举例来说：用户问「北京今天天气」，系统查 API 答一句——这更像带工具的问答，不必强行叫 Agent。用户说「对比三家竞品定价并整理成表发我」，系统自己决定搜谁、抽什么、何时生成表格——这才更接近 Agent。

## 优秀答

过关答之上，我会主动补四块，面试官通常会点头。

### 1. 控制权光谱，而不是三个盒子

真实系统很少是纯的。常见组合：

（1）**Workflow 里嵌 Agent 节点**：主流程固定，某一子任务交给可循环的 Agent。  
（2）**Agent 关键步退化成 Chat**：某一步只生成文案，不再调工具。  
（3）**人在环路（Human-in-the-loop）**：高风险工具（付款、删库、发外部邮件）必须人工确认。

加分句式：「我们对外叫 Agent，对内把高风险路径收成 Workflow + 审批。」这说明你做过生产，不只做过 Demo。

### 2. 能力上限取决于工具与约束，不取决于形容词

Agent 的上限大致是：

（1）工具覆盖面（能读什么、能改什么）。  
（2）模型规划与工具选择质量。  
（3）状态与记忆怎么管。  
（4）评测与护栏是否存在。

没有工具的「Agent」，多半只是会多轮闲聊的 Chatbot。

### 3. 主动说出代价

相对 Workflow，Agent 通常更贵、更慢、更难复现。  
相对 Chatbot，Agent 更容易「自己玩脱」：死循环、重复调用、选错工具。

能把这句话说圆：「我们只在任务开放、规则写不全、且失败可回滚或可人工兜底的地方上 Agent。」比背定义更像中高级。

### 4. 白板一张最小回路

![Agent 最小控制回路](https://ik.imagekit.io/4pjac7gmxh/blog/01-agent-loop_embH61sFA.png)

边画边讲终止条件：最大步数、Token/钱预算、成功判据、用户取消、人工介入。

## 追问清单

**Q1：那 ReAct 算不算 Agent？**  
期望：ReAct 是一种常见实现模式（Thought → Action → Observation），是 Agent 循环的一种写法，不是唯一定义。还可以有 Plan-and-Execute 等。

**Q2：你们和 LangGraph / 某某框架是什么关系？**  
期望：框架是实现手段。先讲控制回路与状态，再讲用了什么库。不要「我们用了 X 所以是 Agent」。

**Q3：多轮 Function Calling 算 Agent 吗？**  
期望：如果模型在多轮里持续决定是否调用工具并朝目标推进，可以算弱/狭义 Agent；若只是「调用一次工具再聊天」，更接近工具增强对话。关键看有没有目标与循环策略。

**Q4：Workflow 里每个节点都是 LLM，是不是就变成 Agent 了？**  
期望：不一定。若边与分支仍由编排器写死，本质仍是 Workflow；只是节点更「聪明」。Agent 强调运行时由模型选择路径。

**Q5：如何向非技术同事解释？**  
期望：Chatbot 像咨询台一问一答；Workflow 像流水线按工序走；Agent 像派一个助理出门办事，你只给目标与规矩，过程中自己判断。

---

## 翻车红旗

（1）「Agent 就是更聪明的 GPT。」——没有机制，只有形容词。  
（2）只背厂商 PPT：自主、多智能体、革命性。——面试官会追问你的终止条件与失败案例。  
（3）把所有带检索的问答都叫 Agent。——边界被你自己抹掉。  
（4）说不清 Chatbot / Workflow / Agent 任一差异，却坚称项目是 Agent。——诚信与抽象能力双杀。  
（5）画不出循环，或循环没有「观察 / 终止」。——说明没落地过。

## 白板提示（30 秒可画完）

```text
用户目标
   ↓
[规划/思考] ←——（未完成）——┐
   ↓                        │
选工具 → 执行 → 观察结果 ——┘
   ↓
终止？ → 输出 / 升级人工
```

旁边标注三列约束：`允许的工具` · `预算/步数` · `必须人工确认的动作`。

---

## 一句话收束

**Agent 是目标驱动、可调用工具的决策循环；Chatbot 是对话驱动的文本交互；Workflow 是规则驱动的预定义路径。**  
面试里先讲清控制权在谁手里，再谈框架与产品名。
