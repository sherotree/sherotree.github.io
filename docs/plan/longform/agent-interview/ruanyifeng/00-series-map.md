# Agent 工程师面试题：一份地图

Agent（智能体）面试题很多。名词也多：Tool Calling、ReAct、RAG、Eval、沙箱……

材料一多，就容易两件事同时发生：要么从头背到尾，要么只记住几个框架名。

本文是我给本系列整理的一张地图。它说明：系列写给谁、每篇怎么读、57 题怎么分模块，以及建议怎么刷。

正题从第 1 篇开始。那一篇才讲「什么是 Agent」。

## 一、这系列解决什么问题

本系列要解决一件很具体的事：把「Agent / LLM 应用工程师」面试里常被追问的内容，按轮次过一遍。

它不是概念词典，也不是某个框架的说明书。

每一篇都按面试现场来组织：你会听到什么问法、过关答到哪、加分答到哪、哪句一出口就危险。

读完你至少该清楚三件事：

（1）答到哪算过关。  
（2）答到哪算加分。  
（3）哪些说法是翻车红旗。

---

## 二、写给谁，不太写给谁

适合你，如果你大致符合下面几条：

（1）做过后端或全栈，最近在往 AI 应用转。  
（2）调过 API，写过 Prompt，搭过简单 RAG 或 Tool Calling。  
（3）马上要面，或预计半年内会面：Agent Engineer、LLM Application Engineer、偏应用侧的 AI Platform。

不太适合你，如果：

（1）还没写过一行调用大模型的代码——建议先做两个小项目再回来。  
（2）只想背名词过关——这里会反复追问「你会怎么设计」。  
（3）期待「包过」或内推话术——没有。

岗位名字各地不一样。你看到 JD 里出现 Agent、Tool Calling、RAG、Eval、沙箱、成本与观测，基本都在本系列覆盖范围内。

## 三、每篇长什么样

正题（第 1～57 题）结构固定，方便当闪卡用。下面是骨架。

```text
【原题】面试官可能怎么问
【考察点】知识点 · 工程判断 · 表达
【过关答】Junior / Mid 的完整答法
【优秀答】带数字、取舍、踩坑、生产约束
【追问清单】常见追问 + 期望答到哪
【翻车红旗】空话与答非所问
【白板 / 示意】（部分题）
```

你可以这样用：

（1）先自己闭卷答 5 分钟。  
（2）对过关答，看缺口。  
（3）再看优秀答和追问，补「加分层」。  
（4）把红旗抄进自己的「禁用句」清单。

说明：本目录是「阮一峰向」叙事版，章节会写成科普笔记；原版目录则更像题库模板。两者知识点一致，结构不同。

## 四、12 个模块，一共 57 题

整季按面试从浅到深排。蓝区打概念与工具底，青区上评测与生产，橙区做系统设计与行为面。

| 模块 | 主题 | 题数 | 你会练到什么 |
|---|---|---|---|
| M1 | 基础概念与边界 | 6 | Agent 是什么、何时不用、ReAct、采样、延迟 |
| M2 | Prompt / Context | 5 | System Prompt、Context Engineering、长上下文、缓存 |
| M3 | Tool Calling / MCP | 6 | 调用链路、schema、路由、失败与 HITL |
| M4 | RAG 与 Agent 检索 | 5 | Agent 场景下的检索、Chunking、评测 |
| M5 | 单 Agent 架构 | 5 | Coding Agent、终止条件、Planner、混合工作流 |
| M6 | Multi-Agent | 5 | 何时该拆、拓扑、上下文传递、失败隔离 |
| M7 | Memory / 长任务 | 4 | 记忆分层、checkpoint、队列与污染治理 |
| M8 | Eval / 可靠性 | 5 | 如何证明变好、离线在线、轨迹评测、回归集 |
| M9 | 安全与合规 | 4 | Injection、权限、沙箱、日志与 PII |
| M10 | 生产：成本 · 延迟 · 观测 | 5 | 估成本、路由、埋点、限流、多租户 |

第 1 题会从边界开始：什么是 Agent，它和 Chatbot、Workflow 差在哪。

## 五、建议怎么刷

### 5.1 没面试、先打底（约 3～4 周）

按模块顺序读：M1 → M3 → M5 → M8 → M9。

先建立「边界、工具、单 Agent、评测、安全」五块肌肉。M2、M4、M6、M7 可以穿插。

### 5.2 两周内要面试

优先这 8 题（高频且容易拉开差距）：

（1）1.1 边界  
（2）1.2 何时不用 Agent  
（3）3.1 Function Calling 链路  
（4）5.1 Coding Agent 设计  
（5）8.1 如何证明变好了  
（6）9.1 Prompt Injection  
（7）10.1 成本估算  
（8）11.2 客服 Agent 系统设计  

其余题当查漏补缺，不要从 M12 倒着背。

### 5.3 已经在做 Agent 线上系统

可以直接从 M8、M9、M10、M11 开始，用你自己的线上事故当「优秀答」素材。

前面模块用来校对术语，避免面试时口语和行业说法对不上。

（1）答案会随模型与协议演进修订；文中会尽量写清「答法背后的判断」，而不是绑死某一个厂商 API 细节。  
（2）本系列是面试向压缩，不是某框架教程。想深挖工程实现，应再对照你自己的项目或更长的专题文。

## 七、阅读时请自备的诚实态度

面试官真正想听的，往往不是「我用过某某框架」。

而是：

（1）你能不能判断「这题该不该上 Agent」。  
（2）你能不能画清楚控制回路：模型、工具、状态、人。  
（3）你能不能讲失败：超时、幻觉、越权、成本爆炸时怎么办。

所以本系列会故意写「翻车红旗」。

如果你发现自己常落在红旗里，那不是丢脸，是定位复习点。
