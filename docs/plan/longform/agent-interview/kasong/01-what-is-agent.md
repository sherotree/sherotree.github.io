# 你简历上的 Agent，面试官可能不认

> 文风版本：**卡颂向**（对照原文 [`../01-what-is-agent.md`](../01-what-is-agent.md)）  
> 系列第 1 题 · 图片复用  
> [地图](./00-series-map.md) · [下一题：很多上 Agent 的需求，我会先否掉](./02-when-not-to-use-agent.md)

大家好。

这两年，几乎所有 AI 项目都爱给自己挂上 Agent（智能体）三个字。

简历更好看。融资更好讲。Demo 更好喊。

但面试官问的第一句，往往很杀气：

「你做的到底是 Agent，还是 Chatbot（聊天机器人），还是 Workflow（工作流）？控制权在谁手里？」

很多人在这一句就露馅。

不是技术不够，是坐标系错了：把产品文案当成了架构定义。

本文把这道题拆开。原题、过关答、加分项、追问、翻车红旗，都在下面。

---

## 原题长什么样

中文常见问法：

> 你怎么定义 Agent？它和 Chatbot、Workflow 有什么区别？你们项目里为什么叫 Agent，而不是「多轮对话」或「流程引擎」？

英文常见问法：

> What is an AI agent? How is it different from a chatbot or a deterministic workflow?

考察点其实就四个：边界清不清、控制权讲不讲、承不承认失败、画不画得出来。

---

## 先换坐标系：问「谁决定下一步」

别从「自主」「智能」开始。那是形容词。

简单来说，三者差在**下一步由谁拍板**：

- **Chatbot**：人持续提问驱动。主产出是文本。可以多轮，也可以接检索。通常没有「模型自己选工具、执行、观察、再决策」的闭环。
- **Workflow**：规则图或编排器拍板。LLM 可以是其中一个节点。路径可预测、可回放、好审计。
- **Agent**：在工具集和策略墙里，由模型朝着一个**目标**做循环决策。典型回路：思考 → 选工具 → 执行 → 观察 → 再思考，直到停。

![Chatbot、Workflow、Agent 三者边界](https://ik.imagekit.io/4pjac7gmxh/blog/01-boundary_ewRcIPoWV.png)

所以我判断是不是 Agent，不看名字，看三点：

1. 有没有目标驱动的多步循环
2. 下一步是否主要由模型决策（在允许范围内）
3. 有没有终止条件：步数、预算、成功判据、人工打断

举个很土的例子。

「北京今天天气？」系统查一次 API 答一句——这是带工具的问答，犯不着叫 Agent。

「对比三家竞品定价，整理成表发给我」——系统自己决定搜谁、抽什么、何时出表——这才更接近。

## 过关之后，面试官想听的是光谱，不是三个盒子

真实系统很少纯。

常见组合：

- Workflow 里嵌一个 Agent 节点：主干死，局部活
- Agent 某一步退化成只生成文案：局部又变回 Chat
- 人在环路（Human-in-the-loop）：付款、删库、对外发信，必须人点头

加分句我见过最管用的是这句：

「我们对外叫 Agent，对内把高风险路径收成 Workflow + 审批。」

这意味着：你做过生产，不只做过 Demo。

能力上限也不取决于形容词。它取决于：

- 工具覆盖面
- 模型规划和选工具的质量
- 状态怎么管
- 评测和护栏在不在

没有工具的「Agent」，多半只是会闲聊的 Chatbot。

还有一句必须主动说：Agent 通常更贵、更慢、更难复现；也更容易自己玩脱——死循环、重复调用、选错工具。

「我们只在任务开放、规则写不全、且失败可回滚或可兜底的地方上 Agent。」

这句话比背定义更像中高级。

![Agent 最小控制回路](https://ik.imagekit.io/4pjac7gmxh/blog/01-agent-loop_embH61sFA.png)

边画边讲终止条件。画不出来，基本就是没落地过。

## 追问来了你怎么接

**ReAct 算不算 Agent？**  
算一种循环写法（Thought → Action → Observation），不是唯一定义。还有 Plan-and-Execute 等。

**所以你们用了 LangGraph？**  
框架是手段。先讲回路和状态，再讲库。不要「用了 X 所以是 Agent」。

**多轮 Function Calling 算吗？**  
如果模型在多轮里持续朝目标选工具，可以算弱/狭义 Agent。调一次工具再聊天，更像工具增强对话。

**Workflow 每个节点都是 LLM，是不是就变成 Agent 了？**  
不一定。边还是编排器写死的，本质仍是 Workflow，只是节点更聪明。Agent 强调运行时由模型选路径。

**怎么跟非技术同事讲？**  
Chatbot 像咨询台一问一答；Workflow 像流水线；Agent 像派助理出门办事——你给目标和规矩，过程中他自己判断。

---

## 这些话一出口就危险

- 「Agent 就是更聪明的 GPT。」没有机制。
- 背厂商 PPT：自主、多智能体、革命性。下一句就会问你的终止条件和事故。
- 所有带检索的问答都叫 Agent。边界是你自己抹掉的。
- 说不清差异，却坚称项目是 Agent。诚信和抽象能力一起扣。
- 循环没有「观察 / 终止」。

白板 30 秒可以只画这个：

```text
用户目标
   ↓
[规划/思考] ←——（未完成）——┐
   ↓                        │
选工具 → 执行 → 观察结果 ——┘
   ↓
终止？ → 输出 / 升级人工
```

旁边三列：`允许的工具` · `预算/步数` · `必须人确认的动作`。

---

## 总结

Agent 是目标驱动、可调用工具的决策循环。  
Chatbot 是对话驱动的文本交互。  
Workflow 是规则驱动的预定义路径。

面试里先讲清控制权在谁手里，再谈框架名。

这个判断带偏见：我把「文案里的 Agent」和「架构里的 Agent」拆开。对写简历的人可能不友好，对过技术面却很友好。
