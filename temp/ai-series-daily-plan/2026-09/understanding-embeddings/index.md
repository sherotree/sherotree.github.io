Embedding（嵌入）是把文本变成一串数字向量。**语义相近的文本，向量在空间里距离更近**——这是 RAG、语义搜索、推荐排序的共同基础。

「向量」「余弦相似度」听起来抽象，但核心动作很具体：把「找相似」变成「算距离」。

下面是我整理的 embedding 最小理解：它在算什么，以及相似搜索怎么落地。

![Embedding 向量空间中相近的点](https://ik.imagekit.io/4pjac7gmxh/blog/2026/09/embeddings-vector-space_JYBdF7cJ8.png)

## 一、先说一个具体麻烦

你有一个 FAQ 知识库，用户搜「怎么退款」。库里写的是「退货流程与金额返还说明」——关键词对不上，传统全文检索可能 miss。

Embedding 的思路是：把问题和文档都变成向量，**比的是语义距离，不是字面匹配**。「退款」和「金额返还」在向量空间里往往靠得很近。

## 二、Embedding 在算什么

简单说，embedding 模型读入一段文本，输出一个固定维度的浮点数组，例如 1536 维：

```json
{
  "input": "退货流程与金额返还说明",
  "embedding": [0.012, -0.034, 0.089, "..."]
}
```

上面代码中，`embedding` 数组就是这段文本的「坐标」。训练目标让语义相似的文本坐标接近、不相似的远离——具体训练方式因模型而异，但使用侧只需记住：**向量 ≈ 语义指纹**。

## 三、相似搜索怎么做

常见流程如下。

（A）**离线**：把知识库每段文本切成 chunk，逐段调 embedding API，存入向量数据库。  
（B）**在线**：用户问题同样变成向量。  
（C）**检索**：在库里找与问题向量最近的 top-k 条（通常用余弦相似度或内积）。  
（D）**返回**：把命中的原文片段交给下游（例如拼进 Prompt 做 RAG）。

![相似搜索流程：查询 → 向量化 → Top-K](https://ik.imagekit.io/4pjac7gmxh/blog/2026/09/embeddings-similarity-search_kjtU28XBl.png)

余弦相似度的直觉：两个向量夹角越小，相似度越高（值域通常 0～1 或 -1～1，视实现而定）。

```python
import numpy as np
def cosine(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))
```

上面代码中，返回 1 表示方向完全一致，0 表示正交（无关）。

### 3.1 距离度量怎么选

余弦相似度看「方向」，内积还受向量长度影响。短 query、长文档时，有时要对向量做 L2 归一化再比。工程上同一项目固定一种度量，索引与查询保持一致；换 embedding 模型时，旧向量通常要**整库重算**。

## 四、向量数据库在干什么

离线建库时，每条 chunk 的 embedding 连同原文、元数据一起写入向量库（如 pgvector、Milvus、Pinecone）。查询时库返回 top-k 的 ID 和距离分数，宿主再按 ID 取回原文——**库只存向量与索引，不替你做生成**。

常见索引结构 HNSW 等，是在「速度」与「召回率」之间折中。库很大时，还要考虑分片、过滤（按部门、按日期）与增量更新。

## 五、和关键词检索的对比

| 方式 | 擅长 | 短板 |
| --- | --- | --- |
| 关键词（BM25） | 精确词匹配、专有名词 | 同义改写、跨语言 |
| Embedding | 语义相近、自然语言问法 | 稀有词、数字 ID、极短文本 |

工程上常用**混合检索**：两路各取 top-k，再合并重排（rerank），比单一路更稳。

## 六、常见误区

（1）**相似度高 ≠ 答案对**——只说明语义接近，还要 Grounding 与引用核对（见 Agent 工程笔记 Grounding 篇）。  
（2）**embedding 模型要配套**——索引和查询最好用同一模型、同一版本。  
（3）**chunk 切法影响巨大**—— 段落太长噪声多，太短语义断掉；见本系列 RAG 篇。  
（4）**维度不是越高越好**—— 维度过高可能过拟合训练分布，迁移到新域要重新评估。

## 七、在 RAG 里的位置

Embedding 是 RAG 检索层的算术基础：索引时把 chunk 变成向量，查询时把问题变成向量，近邻搜索决定「哪些段落进 Prompt」。Grounding 则在生成阶段约束模型别偏离这些段落（见 Agent 工程笔记 Grounding 篇）。没有靠谱的 embedding，后面两步都建在沙上。

OpenAI、Cohere、开源 BGE 等各有适用域。中文为主的库，优先选中文语料训练或评测更好的模型；英文技术文档为主，则英文 embedding 往往更稳。换模型意味着**重跑索引**，这是 RAG 运维里常见的一次性成本。

## 八、小结

Embedding 把文本映射到向量空间，让「找相似」变成「找近邻」。它是 RAG 检索层的核心算术，也是语义搜索从概念到工程的第一步。

下一篇 RAG 会把 embedding 结果怎么用讲完整；Grounding 篇则讲检索命中之后，生成如何不跑题。三篇连读，检索链就闭环了。

若你只做关键词搜索，遇到「用户问法与文档用词不一致」仍会 miss。Embedding 的价值正在这里：把改写、同义、口语化问法映射到相近向量，让检索对自然语言更宽容。

实践里还可加 **rerank 模型**：向量检索先召回 50 条，再用交叉编码器精排 top-5，精度 often 明显提升，延迟略增。Embedding 负责「宽召回」，rerank 负责「准排序」——这是工业 RAG 的常见两阶段结构。
