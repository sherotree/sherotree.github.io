# 保守点，很多「上 Agent」的需求，我会先否掉

> 文风版本：**卡颂向**（对照原文 [`../02-when-not-to-use-agent.md`](../02-when-not-to-use-agent.md)）  
> 系列第 2 题 · 图片复用  
> [上一题](./01-what-is-agent.md) · [下一题：ReAct 和先计划再执行，谁也不该一统](./03-react-vs-plan-execute.md)

大家好。

上一题讲边界：什么叫 Agent。

这一题才是中高级分水岭。

我最近看到太多「我们全面 Agent 化」的焦虑和口号。

听着很潮。落到生产里，往往很贵，有时还很危险。

面试官其实在等你做一件反潮流的事：**清晰地否决 Agent**。

举不出三个具体场景，这题基本就过不去。

本文聊聊：什么时候不该用，替代方案是什么，灰色地带怎么切。

---

## 原题

> 什么时候不该用 Agent？请举三个你会明确否决的场景，并说明替代方案。

英文就是：When would you choose not to use an agent?

考察点不是「你会不会用」，是「你克不克制」。

场景要带失败后果。替代要说得出：Workflow、规则、单次 LLM、人工。

---

## 判断句先扔出来

路径能被可靠写清、失败代价高、或必须可复现时，我优先 Workflow / 规则 / 人工。

只有路径开放、规则写不全、且失败可回滚或可兜底时，才上 Agent。

重申一下：不该用，通常不是模型不够聪明，而是你不该把下一步决策权交给它。

![何时不上 Agent：快速否决清单](https://ik.imagekit.io/4pjac7gmxh/blog/02-when-not_GlXreVw6u.png)

## 三个我会否决的场景

### 步骤已经是 SOP

发票抽取 → 校验税号 → 写入 ERP。

输入输出清楚，异常码清楚。让模型「探索」流程，只增加随机性和费用。

替代：确定性编排。LLM 最多当一个抽取节点。

### 失败不可回滚，或碰合规红线

对外付款、删生产数据、监管报送。

选错工具或参数，损失难逆。

替代：审批流；或「只读 Agent 出草案，人点确认」。执行层仍是受控 API，不给模型终态权限。

### 必须同路径可复现

对账、计价、法务条款要比对出同一条证据链。

Agent 同输入不同路径，审计会疯。

替代：固定流水线 + 全量日志。LLM 只建议，规则引擎说了算。

三个场景共性就一句：**运行时不该让模型去探索控制权。**

---

## 上线前五问，任一「是」就放慢

1. 步骤是否已能画成稳定流程图？
2. 最坏失败是否不可逆或违法？
3. 是否要求同输入同路径可回放？
4. 延迟 / 成本是否扛不住多步循环？
5. 工具少到「循环」没有意义？

灰色地带更常见。比如客服 80% 标准问答 + 20% 开放问题。

标准走 Workflow / 检索；开放再进 Agent，并加步数和权限顶。

这比「全部 Agent」或「全部死流程」都更像人在做产品。

还有一句很现实：技术上可行，不等于产品上该用。多步循环把毛利打穿，就该降级成单次调用或模板。

加分口吻可以很具体（换成你自己的项目）：

「有人提议用 Agent 自动改生产配置。我否决了。配置必须走变更单和双人复核。Agent 只生成草案。」

面试官听的是判断，不是勇气。

---

## 追问

**Demo 能不能先上 Agent？**  
能。但要标明是原型。上线门禁单独过否决清单，架构不要原样毕业。

**那为什么 Coding Agent 满地都是？**  
写代码路径高度开放，编译测试反馈密，失败常能 git 回滚。优势区对得上。不代表你的 ERP 能照搬。

**同事狂热怎么办？**  
对齐差错率、审计、成本。给替代和试点边界。别道德批判。

**工具很多但权限都很大？**  
先砍权限和 HITL。否决的是「裸 Agent」，不是自动化本身。

---

## 翻车红旗

- 「简单任务不用」——没定义什么叫简单
- 三个场景其实是同一句换皮
- 否决完只剩「那就人工」，没有流程
- 为显得新潮，坚持全面 Agent 化
- 把「模型不准」当唯一否决理由。不准可以评测和护栏；硬否决往往是控制权与后果

白板就两列：

```text
可用 Agent          不要 Agent
开放目标            固定 SOP
失败可回滚          失败不可逆
反馈密              必须同路径复现
有步数/预算墙       无护栏 / 权限过大
```

中间写：`先问控制权与后果，再问用不用模型。`

---

## 总结

能清晰否决，比会喊 Agent 更像工程师。

这个分析很主观：我把「潮」和「该」拆开。对写融资稿的人可能扫兴，对过技术面刚刚好。
