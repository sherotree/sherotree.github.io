## 一、多平台怎么复用

| 平台 | 侧重点 | 同一选题怎么改 |
|------|--------|----------------|
| 掘金 | 前端 / AI 工程 / 效率 | 标题偏技术，代码与踩坑可多一点 |
| CSDN | 搜索长尾、教程完整 | 标题用「入门 / 详解 / 理解」；结构更全 |
| 微信公众号 | 完读与转发 | 缩短约 10%～20%，少大段代码 |
| 博客园 | 长文、工程向读者 | 可保留完整教程体；分类打准（前端 / AI / 随笔） |
| SegmentFault 思否 | 开发者问答气质 | 标题可偏「问题 + 解法」；适当保留可复制代码 |
| 开源中国 | 开源 / 工具链 / 工程 | 偏开源实践、协议、本地部署、工程效率；少营销腔 |

固定节奏建议：**周二 / 周四 / 周六** 各 1 篇；第 4 篇仅用于热点或补更。

**生产只做一次，分发做六次：**

1. 先在本仓库 `src/content/blog/` 写 Markdown 长文（母稿）  
2. **全文同步优先**：CSDN、掘金、博客园、思否、开源中国（结构可几乎相同，只改标题与标签）  
3. **公众号单独改编**：删减版，配封面  

六站头像与简介统一（「把复杂技术讲清楚」），简介暂不挂工具站。  
发布顺序建议：CSDN → 掘金 → 思否 → 博客园 → 开源中国 → 公众号（公众号可晚半天，避免纯搬运感）。

若某周精力不够：**母稿 + 至少发出 CSDN / 掘金 / 公众号** 为底线；博客园 / 思否 / 开源中国可次日补发，但不要积压超过 1 周。

## 六、每周执行

1. **周一**：锁定 3 题；热点最多替换其中 1 题。  
2. **写稿**：按 `ruanyifeng-tech-writing`；发布前检查导流纪律——第 1～6 周全文不出现自有域名；第 7 周起仅允许文末一行主站归档链接，其余导流话术仍为零。  
3. **发布**：六站按建议顺序同步；评论区只聊技术。底线三站（CSDN / 掘金 / 公众号）当天发完，其余 24 小时内补齐。
4. **周日**：记录阅读、推荐、搜索词、净增关注；连续两周低迷的题型从池子里换掉。
