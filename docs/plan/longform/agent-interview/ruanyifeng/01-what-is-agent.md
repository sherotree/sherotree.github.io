# 理解 Agent：它和 Chatbot、Workflow 的边界

> 系列：[地图](./00-series-map.md) · 下一篇：[什么时候不该用 Agent](./02-when-not-to-use-agent.md)

Agent（智能体）这个词现在到处都是。产品文案里有，简历里也有。

难处在于：不同的人说的不是同一件事。有人把多轮聊天叫 Agent，有人把流程图里塞几个大模型节点也叫 Agent。

本文用控制权这把尺子，把 Chatbot、Workflow、Agent 分开讲清。讲完你就可以按面试口径答：「什么是 Agent，它和另外两者差在哪。」

---

## 一、面试官通常怎么问

中文常见问法：

> 你怎么定义 Agent？它和 Chatbot、Workflow（工作流）有什么区别？你们项目里为什么叫 Agent，而不是「多轮对话」或「流程引擎」？

英文常见问法：

> What is an AI agent? How is it different from a chatbot or a deterministic workflow?

考察点大致有四个：

（1）有没有清晰边界，而不是背「自主」「智能」空话。  
（2）能不能从控制权讲：谁决定下一步——人、规则图，还是模型。  
（3）是否承认失败模式：循环、成本、不可预测性。  
（4）表达是否能画出来（白板友好）。

---

## 二、先用一个生活场景

设想你要办三件事。

第一件：你在窗口问「附近哪家医院能看牙」，对方答一句。这是咨询台——一问一答。

第二件：你办护照，窗口把材料按固定工序往下传，缺哪页就退回哪页。这是流水线——步骤事先写好。

第三件：你对助理说「帮我订下周三去上海、总价可控的行程」，对方自己查航班、比价、问你偏好、再下单。这是派出去办事——你给目标与规矩，过程中他自己判断。

简单说：

（1）Chatbot 像咨询台。  
（2）Workflow 像流水线。  
（3）Agent 像派出去办事的助理。

正式定义放在下一节。上面这个类比，面试里对非技术同事也够用。

---

## 三、三个概念分别是什么

**Chatbot（聊天机器人）**：以对话为界面，主产出是文本。可以多轮，也可以接检索，但通常没有「模型自己选工具、执行、再观察、再决策」的闭环。下一步多半由用户继续提问驱动。

**Workflow（工作流）**：步骤事先画在图里，或写在编排代码里。大模型可以是其中一个节点，但分支与顺序主要由规则或编排器决定。可预测、易回放、易审计。

**Agent（智能体）**：给一个目标，在工具集与策略约束下，由模型在循环里决定「想什么、调什么工具、何时停」。典型回路是：思考 → 选工具 → 执行 → 观察 → 再思考，直到满足终止条件。

![Chatbot、Workflow、Agent 三者边界](https://ik.imagekit.io/4pjac7gmxh/blog/01-boundary_ewRcIPoWV.png)

所以，我判断是不是 Agent，不看产品文案里有没有这个词，而看三点：

（1）有没有目标驱动的多步循环。  
（2）下一步是否主要由模型决策（在允许的工具与策略内）。  
（3）有没有明确的终止条件（步数、预算、成功判据、人工打断）。

举例来说：用户问「北京今天天气」，系统查 API 答一句——这更像带工具的问答，不必强行叫 Agent。用户说「对比三家竞品定价并整理成表发我」，系统自己决定搜谁、抽什么、何时生成表格——这才更接近 Agent。

## 四、过关答可以怎么组织

面试里不必先讲论文。用三句话立边界，再展开例子，通常就够过关。

（1）Chatbot：对话驱动，主产出文本。  
（2）Workflow：规则驱动，路径预定义。  
（3）Agent：目标驱动，模型在工具约束下循环决策。

然后补一句代价：相对 Workflow，Agent 通常更贵、更慢、更难复现；相对 Chatbot，Agent 更容易死循环、重复调用、选错工具。

能把这句话说圆，就很像中高级：

「我们只在任务开放、规则写不全、且失败可回滚或可人工兜底的地方上 Agent。」

## 五、优秀答通常多讲什么

过关之上，面试官常会点头的四块如下。

### 5.1 控制权是光谱，不是三个盒子

真实系统很少是纯的。常见组合：

（1）Workflow 里嵌 Agent 节点：主流程固定，某一子任务交给可循环的 Agent。  
（2）Agent 某步退化成 Chat：某一步只生成文案，不再调工具。  
（3）人在环路（Human-in-the-loop）：高风险工具必须人工确认。

加分句式：「我们对外叫 Agent，对内把高风险路径收成 Workflow + 审批。」这说明你做过生产，不只做过 Demo。

### 5.2 能力上限取决于工具与约束

Agent 的上限大致是：

（1）工具覆盖面（能读什么、能改什么）。  
（2）模型规划与工具选择质量。  
（3）状态与记忆怎么管。  
（4）评测与护栏是否存在。

没有工具的「Agent」，多半只是会多轮闲聊的 Chatbot。

### 5.3 主动说出代价

贵、慢、难复现、容易玩脱——主动讲，比等面试官追问更稳。

### 5.4 白板画一张最小回路

![Agent 最小控制回路](https://ik.imagekit.io/4pjac7gmxh/blog/01-agent-loop_embH61sFA.png)

边画边讲终止条件：最大步数、Token / 钱预算、成功判据、用户取消、人工介入。

下面是一个 30 秒可画完的骨架。

```text
用户目标
   ↓
[规划/思考] ←——（未完成）——┐
   ↓                        │
选工具 → 执行 → 观察结果 ——┘
   ↓
终止？ → 输出 / 升级人工
```

上面示意中，缺「观察」或「终止」的环，通常说明还没落地过。旁边可标注三列约束：允许的工具、预算 / 步数、必须人工确认的动作。

## 六、常见追问

**Q1：那 ReAct 算不算 Agent？**  
ReAct 是一种常见实现模式（Thought → Action → Observation），是 Agent 循环的一种写法，不是唯一定义。还可以有 Plan-and-Execute 等。

**Q2：你们和某某框架是什么关系？**  
框架是实现手段。先讲控制回路与状态，再讲用了什么库。不要说「我们用了 X 所以是 Agent」。

**Q3：多轮 Function Calling 算 Agent 吗？**  
如果模型在多轮里持续决定是否调用工具并朝目标推进，可以算弱 / 狭义 Agent；若只是「调用一次工具再聊天」，更接近工具增强对话。关键看有没有目标与循环策略。

**Q4：Workflow 里每个节点都是 LLM，是不是就变成 Agent 了？**  
不一定。若边与分支仍由编排器写死，本质仍是 Workflow；只是节点更「聪明」。Agent 强调运行时由模型选择路径。

**Q5：如何向非技术同事解释？**  
用第二节的咨询台 / 流水线 / 助理即可。

## 七、翻车红旗

（1）「Agent 就是更聪明的 GPT。」——没有机制，只有形容词。  
（2）只背厂商 PPT：自主、多智能体、革命性。——会被追问终止条件与失败案例。  
（3）把所有带检索的问答都叫 Agent。——边界被自己抹掉。  
（4）说不清三者任一差异，却坚称项目是 Agent。  
（5）画不出循环，或循环没有观察 / 终止。

---

## 八、一句话收束

Agent 是目标驱动、可调用工具的决策循环；Chatbot 是对话驱动的文本交互；Workflow 是规则驱动的预定义路径。

面试里先讲清控制权在谁手里，再谈框架与产品名。

下一篇会反过来问：什么时候不该用 Agent。
