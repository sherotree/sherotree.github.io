# Agent 面试｜第 0 题｜57 题地图：怎么刷、本系列怎么更新

本系列要解决一件很具体的事：帮你把「Agent / LLM 应用工程师」面试里常被追问的内容，按轮次过一遍。

不是概念词典，也不是框架说明书。

每一篇都按面试现场来写：原题、考察点、过关答、优秀答、追问、翻车红旗。

读完你该清楚三件事：答到哪算过关，答到哪算加分，哪句一出口就危险。

下面是整季地图、刷题顺序，以及更新节奏。

![Agent 工程师面试 12 模块地图](https://ik.imagekit.io/4pjac7gmxh/blog/00-module-map_FBn9SV0ET.png)

## 一、这系列写给谁

适合你，如果你大致符合下面几条：

（1）做过后端或全栈，最近在往 AI 应用转。  
（2）调过 API，写过 Prompt，搭过简单 RAG 或 Tool Calling。  
（3）马上要面，或预计半年内会面：Agent Engineer、LLM Application Engineer、偏应用侧的 AI Platform。

不太适合你，如果：

（1）还没写过一行调用大模型的代码——建议先做两个小项目再回来。  
（2）只想背名词过关——这里会反复追问「你会怎么设计」。  
（3）期待「包过」「内推话术」——没有。

岗位名字各地不一样。你看到 JD 里出现 Agent、Tool Calling、RAG、Eval、沙箱、成本与观测，基本都在本系列覆盖范围内。

## 二、每篇长什么样

正题（第 1～57 题）结构固定，方便当闪卡用：

```text
【原题】
面试官可能怎么问（中文为主，必要时附英文说法）

【考察点】
知识点 · 工程判断 · 表达是否清楚

【过关答】
Junior / Mid 拿到 offer 的完整答法

【优秀答】
带数字、取舍、踩坑、生产约束

【追问清单】
3～6 个常见追问 + 期望答到哪

【翻车红旗】
空话、只会背框架名、答非所问

【白板 / 示意】（部分题）
一张草图或伪代码骨架
```

你可以这样用：

（1）先自己闭卷答 5 分钟。  
（2）对过关答，看缺口。  
（3）再看优秀答和追问，补「加分层」。  
（4）把红旗抄进自己的「禁用句」清单。

## 四、建议怎么刷

### 4.1 没面试、先打底（约 3～4 周）

按模块顺序读：M1 → M3 → M5 → M8 → M9。

先建立「边界、工具、单 Agent、评测、安全」五块肌肉。M2、M4、M6、M7 可以穿插。

### 4.2 两周内要面试

优先这 8 题（高频且容易拉开差距）：

（1）1.1 边界  
（2）1.2 何时不用 Agent  
（3）3.1 Function Calling 链路  
（4）5.1 Coding Agent 设计  
（5）8.1 如何证明变好了  
（6）9.1 Prompt Injection  
（7）10.1 成本估算  
（8）11.2 客服 Agent 系统设计  

其余题当查漏补缺，不要从 M12 倒着背。

### 4.3 已经在做 Agent 线上系统

可以直接从 M8、M9、M10、M11 开始，用你自己的线上事故当「优秀答」素材。

前面模块用来校对术语，避免面试时口语和行业说法对不上。

## 五、本系列怎么更新

发布平台：博客园，分类建议用「Agent工程师面试」。

节奏：每周三更，默认周一、周三、周五各一篇正题。

标题统一为：

`Agent 面试｜第 N 题｜<短题干>`

文末会挂「上一题 / 下一题」。你也可以按分类列表顺序读。

说明两点预期：

（1）答案会随模型与协议演进修订；文中会尽量写清「答法背后的判断」，而不是绑死某一个厂商 API 细节。  
（2）本系列是面试向压缩，不是某框架教程。想深挖工程实现，应再对照你自己的项目或更长的专题文。

## 六、阅读时请自备的诚实态度

面试官真正想听的，往往不是「我用过 LangGraph」。

而是：

（1）你能不能判断「这题该不该上 Agent」。  
（2）你能不能画清楚控制回路：模型、工具、状态、人。  
（3）你能不能讲失败：超时、幻觉、越权、成本爆炸时怎么办。

所以本系列会故意写「翻车红旗」。

如果你发现自己常落在红旗里，那不是丢脸，是定位复习点。
