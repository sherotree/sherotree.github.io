## 一、为什么先砍到长文 + 短内容

旧计划把长文（~344 篇）、短内容（即刻 / Reddit / X / LinkedIn / GitHub）、音频、视频、邮件一起铺开，周耗时 22–35 小时，接近全职。

| 形态 | 沉淀 | 复用 | 冷启动成本 | 本期 |
|---|---|---|---|---|
| 长文（博客 / 知乎 / 公众号 / 少数派） | 高 · SEO / 权威 | 可拆成短内容 / 日后视频脚本 | 中 | ✅ 主线 |
| 短内容（即刻 / X / Reddit / 小红书） | 中 · 算法 + 关系 | 依赖长文素材池 | 低 | ✅ 放大器 |
| 视频 / 播客 / Newsletter | 高但生产重 | 可后剪 | 高 | ⏸ 暂缓 |

## 二、内容双轨

```
                    ┌─────────────────────────────┐
                    │  长文主库（个人博客）           │
                    │  一篇 = 完整论点 + 数字/截图    │
                    └──────────────┬──────────────┘
                                   │ 同日 / 次日拆
          ┌────────────────────────┼────────────────────────┐
          ▼                        ▼                        ▼
   中文短内容                 英文短内容                  图文短内容
   即刻 · X 中文圈            Reddit / IH · X EN         小红书 9 图
```

**一条生产铁律**：先有长文（或至少长文大纲 + 实测素材），再拆短内容。禁止「只发短内容、长文永远不写」。

### S1 · 即刻 · 今日 AI 产品（100 条）

```
【产品名】<一句话钩子>

一句话：<产品定位>

我看好 / 我怀疑：
- <点 1>
- <点 2>

链接：<官网>
#今日AI产品
```

分区建议：Vertical SaaS → Agent 工具 → 内容创作 → 硬件/玩具（各约 25）。  
发帖：工作日 12:00；周末可停（可持续优先于硬日更）。

### S2 · Reddit / IH · Build in Public（100 天）

```
Day X / 100

What I did today:
- …

Numbers:
- Users / MRR / Signups

Lesson:
<one-liner>
```

与 Solopreneur 长文共用同一项目；每 10 天可发一条 Milestone 长贴，链回博客英文摘要或原文。

### S3 · X · 长文拆条

每篇 P0 长文发布当天或次日：

```
1/  反常识数字或结论（钩子）
2–7/ 过程 · 决策 · 证据
末帖/ 全文链接 + 一句 CTA
```

Solopreneur 类主打「真实数字」；AI 原理类主打「一个类比 + 一张图」。

### S4 · 术语钩子（冷启动用）

从 [`longform/ai-terms-explained.md`](./longform/ai-terms-explained.md) 抽 30 条，格式：

```
<术语英文>｜一句话生活类比

大多数人以为：…
实际上：…

想看完整 30 词地图 → <博客链接>
```

30 条发完后，改从 AI Phase 1 新文拆「一个误解」。
