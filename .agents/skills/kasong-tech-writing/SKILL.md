# 卡颂风格中文前端写作

基于 [魔术师卡颂掘金主页](https://juejin.cn/user/1943592291009511/posts?sort=popular) 按阅读量排序的 Top 50 文章提炼的**写作手法**（非冒充本人、不复制原文）。

语料与选题分布见 [corpus.md](corpus.md)。结构模板见 [examples.md](examples.md)。

## 硬约束

1. **只学风格，不抄内容**：不复述其原文段落、个人经历细节、社群话术、金句或独特类比原句。
2. **不冒充**：不要用「大家好，我卡颂」「魔术师卡颂」署名，不暗示作者身份。
3. **事实自担**：技术结论、时间线、融资/版本号必须可核验；不确定就标明不确定。
4. **原创优先**：同类主题用自己的案例、自己的框架、自己的数据。
5. **软广克制**：可保留 0～1 处自然相关延伸；禁止照搬「人类高质量前端群」「打包领取」等话术。

## 选题 DNA（先选题，再动笔）

Top 50 高阅读量文章高度集中在六类（可叠加）：

| 类型 | 读者为什么点 | 典型角度 |
|------|--------------|----------|
| **热点解读** | 刚发生的事，想快速搞懂 | 是什么 → 版图/时间线 → 动机 → 影响 → 会不会成 |
| **趋势预测** | 焦虑未来，想要判断框架 | 现状冲击 → 分析原则 → 阶段模型 → 对从业者含义 |
| **职业/焦虑** | 裁员、AI、独立开发、躺平 | 共鸣场景 → 拆错因 → 给可执行框架（常带「不适合多数人」） |
| **学习痛点** | 「我怎么老学不会」 | 复现失败路径 → 指出错误心智模型 → 换一套坐标系 |
| **框架生态争论** | React/Vue/工具链站队 | 争议表面 → 历史脉络 → 设计取舍 → 跳出站队的结论 |
| **反常识揭秘** | 标题与直觉打架 | 日常困惑 → 分层拆机制 → 「原来如此」 |

选题优先满足至少 2 条：

- 有**正在发酵的钩子**（新公司、新版本、爆火工具、裁员/AI 焦虑）
- 能落到**前端工程师自身利益**（门槛、提效、职业路径、选型）
- 有**可复述的分析框架**（阶段论、提效×门槛、压缩/失真、时间线分期）
- 结论可**反直觉或可站队讨论**（但论证要扎实）

少写：纯 API 罗列、无观点的翻译稿、没有「所以呢」的新闻摘要。

## 标题 DNA

标题要像「朋友圈会转发的判断」，不要像文档目录。

### 高转化形态（可组合）

1. **预测/趋势**：`预测X年之后的…` / `从 Y 看 Z 的一个小趋势` / `…预示着前端的未来`
2. **反问/悬念**：`…会一统前端么？` / `…会被干掉吗？` / `…谁会淘汰谁？`
3. **反常识**：`都用 HTTPS 了，还能…？` / `提问量暴跌，却赚翻了？`
4. **强烈断言**：`保守点，90%的…不适合…` / `…，原因很现实`
5. **你需要知道的**：`关于 X，你需要知道的` / `关于 X，你需要了解的前因后果`
6. **省略号钩子**：`Eslint 团队终于妥协了...` / `把…投喂给 GPT 后...`
7. **数字钩子**：`不数不知道，…已经有 N 个…` / `耗时一年半才出第一版…`
8. **口语共鸣**：`为什么我总学不好 TS？` / `最近看到太多…焦虑，有些话想说`

### 标题禁忌

- 空泛大词：`浅谈前端` / `最佳实践汇总`（无冲突、无时间、无对象）
- 纯教程目录体：`如何使用 useEffect`（除非挂在痛点/反常识上）
- 夸张营销腔与堆 emoji

## 文风 DNA（必须遵守）

### 1. 开篇（固定节奏）

用 3～8 个短段，顺序如下（可略删，勿打乱）：

1. **身份句**（改写为自己的，禁止冒充）：如「大家好，我是某某。」
2. **热点/场景落地**：最近什么事、有多热、读者为什么在意（可用一句夸张但不造假的观察）
3. **共鸣痛点或争议**：焦虑 / 纠结 / 站队 / 「明明…却…」
4. **本文承诺**：本文聊聊… / 本文尝试预测… / 让我们详细来聊聊
5. 可选：**分析原则**（尤其预测文）：尊重客观规律、尊重人性、不建立在假想突破上

开篇术语首次出现用：`中文（English，一句解释）`。

### 2. 结构骨架

主线优先：

```text
钩子场景 → 问题重述 → 分析框架（阶段/对比/时间线）
→ 分节拆解（每节只推进一个判断）
→ 反例或边界 → 对「你」意味着什么 → 短总结
```

标题风格的小节优先用**判断句/问题句**，少用「概述」「简介」：

```text
## 范式迁移的本质
## Eslint 与 Prettier 之争
## 学不好的原因
## 阶段1：开发范式迁移
```

### 3. 段落与句子

- 一段一事；多数段落 **1～3 句**
- 口语、短句；像当面讲，不像论文
- 常用衔接：`简单来说`、`所谓…指的是`、`这意味着`、`重申一下`、`恰恰相反`、`但请注意`、`本质上`
- 列表密集：枚举工具、阶段、原因、能力时用短列表，不写空话 bullet
- 中英文之间加空格；全角中文标点；引号优先 `「」`

### 4. 解释手法（最重要）

卡颂爆款的核心不是堆资料，而是**给读者一个能带走的坐标系**：

| 手法 | 用法 |
|------|------|
| **阶段论** | 把混沌拆成 2～3 个阶段（迁移 → 新栈 → 新路径） |
| **双因子模型** | 如「提效 × 提高门槛」解释为何某技术被市场接受 |
| **错误心智模型** | 先复现读者失败路径，再指出坐标系选错了 |
| **历史脉络** | 竞品时间线：谁先出现、解决什么、为何被替代 |
| **类比** | 压缩/失真、快递小区地址 vs 门牌号；**必须自创**，贴合题材 |
| **人性视角** | 程序员是谋生职业；技术再强，赚不到钱就难推广 |
| **承认偏见** | `这个分析很有可能是主观、带有偏见的` —— 敢下判断也敢限缩 |

顺序：场景 → 框架 → 机制细节 → 对从业者的含义。  
坏顺序：先甩规范/源码细节，再补故事。

### 5. 观点姿态

- **敢下结论**，但用机制与历史撑住，不靠骂战
- 常写「跳出站队」：表面是 React vs Vue，实际谈门槛、生态、范式
- 预测文写清边界：基于已有技术，不幻想重大突破
- 职业文常带冷静泼冷水：多数人不适合某条路，但给出「适合谁」

### 6. 代码与配图

- 需要证明类型/协议/API 时给**短**代码；块前有一句「下面看个例子」，块后点 1～3 个关键点
- 概念文可以几乎无代码，靠框架与时间线推进
- 架构/阶段关系可用简图或 Mermaid；不要为配图而配图
- 禁止大段贴源码充字数

### 7. 收尾

- 用 1～3 段收回主结论（趋势 / 机制 / 你该怎么看）
- 可留一句开放式：「既是机遇也是挑战」类收束，但避免空洞鸡汤
- 不要强行多 CTA；若有延伸阅读，最多一处

## 工作流

```text
- [ ] 选题是否踩中：热点 × 利益 × 可带走框架 ×（可选）反常识
- [ ] 标题是否像判断/悬念，而非目录名
- [ ] 开篇是否：身份 → 钩子 → 痛点 → 本文做什么
- [ ] 是否先给分析框架，再进细节
- [ ] 段落是否短、口语、列表清楚
- [ ] 类比是否自创；术语是否首次中英对照
- [ ] 结论是否有边界/偏见声明（需要时）
- [ ] 无冒充卡颂、无抄原文、软广 ≤ 1
```

## 适用 / 不适用

**适用**：掘金/公众号前端热点文、趋势预测、工具链解读、职业思考、痛点科普  

**不适用**：官方文档口吻、纯 Changelog、学术论文体、需要严格引用规范的综述

## 与其他写作 skill 的分工

- 要**短段科普 + 配图教程节奏** → 优先 `ruanyifeng-tech-writing`
- 要**热点钩子 + 行业判断 + 口语观点文** → 用本 skill
- 两者都可时：教程步骤文偏阮，评论/预测/焦虑文偏卡
